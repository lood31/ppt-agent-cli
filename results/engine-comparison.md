# 候选引擎比较与最终选择

## 最终选择

采用固定 `hands-on-deck` 的薄适配，WPS COM 负责动画、切换、原生图表专属操作、最终保存、重开验证和 PDF 导出。

OfficeCLI 不进入 MVP 默认运行时。自研范围只限产品状态机、安全扫描、协议和 WPS 事务适配，没有重写完整 PPTX 引擎。

## 选择依据

| 维度 | hands-on-deck | OfficeCLI | WPS COM |
|---|---|---|---|
| 原子 patch | 已实测 | 静态能力强，未运行 | 不适合作为通用 patch 层 |
| 紧凑 inspect/diff | 已实测 | Schema 强，未运行 | 输出不适合 Agent |
| 默认离线 | 是 | 否，默认更新并支持 URL | 是 |
| 动画创建 | 不支持 | 静态源码显示支持 | 已实测通过 |
| 原生图表 | 不创建 | 静态源码显示支持 | 已实测编辑通过 |
| WPS 最终保真 | 需补 | 未实测 | 已实测通过 |
| 适配成本 | 低 | 安全收口成本高 | 作为尾部能力合适 |

该组合满足“一个事务、WPS 最后写入和验证”的设计约束，同时把未验证的 OfficeCLI 与默认联网行为隔离在产品之外。
