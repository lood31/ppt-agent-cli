## 调用行为、重试与异常

最终六个 Agent 进程均正常退出，没有 API 异常退出或旧 skill 回退。实验内仍有 11 次失败命令，Agent 随后使用结构化错误中的 `corrected_example` 自行修正并完成任务：

- 6 次 `INVALID_INSPECT_FIELDS`：仍把 `slide_index`、`shape_id`、`slides.shapes.*` 等理解成公开字段，而不是使用 `geometry,name,text,type` 等字段组。
- 5 次错误 patch 输入：包括把 `[]` 当文件路径、直接提交 operations 数组或内联 JSON；CLI 均在写入前拒绝，返回 `INVALID_PATCH`，文档未改变。
- 没有读取 `schema apply --full`；所有单项 Schema 输出和 inspect 输出均保持紧凑。
- 没有递归目录枚举、源码搜索、memory 搜索或旧 skill 文档读取。

## 与第 1 轮的变化

相对第 1 轮 B：

- 总 Token 从 `2,071,230` 降至 `1,735,472`，降低 `16.21%`。
- 未缓存输入 + 输出从 `284,990` 降至 `170,672`，降低 `40.11%`。
- 最大单次命令输出从 `34,778 B` 降至 `1,953 B`，完整 Schema 读取从 4 次降至 0 次。
- 错误命令从 12 次降至 11 次，说明输出减负已经生效，但字段发现性和 patch 文件形态仍不够稳定。

因此本轮不是质量失败，也不是输出爆量，而是未缓存成本仍存在小幅缺口。下一步应先分析这 11 次可复现错误及场景 3 的上下文携带，再决定是否做最小接口修正；在指标恢复到 70% 前不追加第 3 轮。
