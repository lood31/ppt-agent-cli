## 波动分析

相对上一轮接口减负 B-only 点估计，本轮总 Token 下降 5.77%，输出 Token 下降 7.35%，工具调用下降 11.71%，耗时下降 9.73%；接口总体成本没有恶化。

失败来自缓存结构波动，而不是输出爆炸：

- 上一轮 B 缓存命中占输入的 `93.90%`，本轮降至 `87.45%`；固定 A 为 `93.82%`。
- 本轮未缓存输入从上一轮的 `132,204` 增至 `256,451`，增加 `93.98%`。
- 本轮“未缓存输入 + 输出”比上一轮增加 `74.83%`；场景 2、5、6 分别增加 `200.31%`、`108.19%`、`96.74%`。
- 四次完整 Schema 查询和 12 次失败命令增加了上下文往返，但实验内文本工具输出合计仅 `235,215 B`，最大单次仍低于 64 KB；它们不能单独解释全部未缓存 Token 波动。

因此当前证据只能说明总 Token 目标通过、质量通过，但未缓存成本不稳定。下一步应先定位缓存命中变化和 CLI 调用失败的来源；在该指标恢复到 70% 后，才值得支付第 2、3 轮复测费用。

## 本轮后定向修复

未调用 API、未扩展 PPT 能力，仅针对上述 12 次确定性错误收紧 Agent 接口：

- `schema apply` 默认返回小于 8 KB 的操作目录；完整联合 Schema 改为显式 `--full`。
- `inspect --fields` 错误返回允许字段和按当前 purpose 生成的 `corrected_example`。
- Patch 与 create JSON 接受 UTF-8 BOM。
- operations 数组错误返回包含当前 `document_id`、`revision`、稳定 `request_id` 和原 operations 的完整包装示例。
- 缺少 `request_id` 时由 CLI 基于文档、revision 和 operations 生成稳定幂等 ID。
- Patch 校验错误统一在适用时携带 `corrected_example` 和 `document_unchanged: true`。

本地验证：`84 passed, 1 xfailed`；重建 EXE 的默认操作目录为 `2,171 B`，完整 `--full` Schema 为 `34,912 B`，默认输出缩小约 93.8%。冻结 EXE SHA-256 为 `E99AF1581A5FCB27BD108B2E90BE8A5512EA5B1C071C0BD70480BF04F47076E5`。

这些修改只消除已观察到的调用摩擦；是否能让“未缓存输入 + 输出”重新达到 70%，仍需下一次完整 B-only 实验验证，不能由本地测试推断。
